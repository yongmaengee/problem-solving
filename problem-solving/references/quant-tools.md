# 정량 도구 (`scripts/quant.py`)

정량 비교의 근거를 문제와 무관하게 같은 방식으로 만든다. 표준 라이브러리만 쓴다. 모든 서브커맨드는 JSON을 출력하고, 결과는 Blueprint 명세에 넣어 캔버스에서 보인다.

| 언제 | 명령 | 무엇을 알려주나 |
|---|---|---|
| 깊이 1~2의 반사실 검정 | `sweep` | 손잡이(길이, 배치, 정밀도, 하이퍼파라미터…) 격자마다 실제로 실행해 측정. 실패(OOM 등)도 경계로 기록 |
| 측정 후 층위 판별 | `scaling` | y = c + a·xᵏ 적합. 지수 k로 상수/선형/제곱/세제곱 판별, 상수항(고정 비용) 분리, 실패 시작 지점 |
| 스텝에 따라 늘어나는가 | `leak` | 누수(텐서 누적·그래프 보존 등) 판별 |
| 6단계 가치 비교 | `table` | 종합 점수·순위, 가중치를 흔들었을 때 1위 확률(견고성), 1·2위를 가르는 축 |
| 결정 지점 | `decide` | 사용자에게 결정을 요청해야 하는지(다섯 사유)와 무응답 시 기본값. `--write`로 명세의 `requests`에 넣음 |
| 루프가 끝날 때 | `delta` | 이전 명세와 비교한 변경량과 절단 판정 (`value-table.md`의 점수표) |

## 사용 원칙
- `sweep`은 가볍고 되돌릴 수 있는 측정에만 쓴다. 측정 스크립트(probe)는 문제 코드에서 측정 대상만 떼어 몇 스텝만 돌리고, stdout 마지막 줄에 JSON 측정값을 출력하게 만든다. 장시간 학습이나 데이터 변경은 sweep 대상이 아니며 사용자 확인을 받는다.
- `sweep --knobs spec.json`은 결과를 명세의 `knobs`로 넣는다. 사용자는 캔버스에서 손잡이를 움직여 미리 측정된 값을 즉시 본다.
- `scaling`은 단순 log-log 기울기를 믿지 않는다. 고정 비용이 큰 구간에서는 지수가 과소평가된다(출력의 `naive_loglog_exponent`와 비교). 측정점은 4개 이상, 범위는 넓게.
- `table`에서 `robust: false`면 1위가 가중치에 달려 있다는 뜻이다. 후보를 더 찾기 전에 무엇을 중시하는지(가중치)를 사용자와 먼저 맞춘다.
- 검정 강도와 맞춘다: 거시 층위에서는 `sweep`을 돌리지 않고 문헌 근거로 점수를 매긴다. `sweep`·`scaling`·`leak`은 깊이 1~2의 도구다.

## 미리 계산하기
검토형 중간 개입에서는 사용자가 무엇을 조절할지 예상해 미리 계산해 둔다.
- 대안 Lens: 지금 Lens 외에 사용자가 옮길 만한 블록(보통 스케일링·파급 분석이 가리키는 블록 1~2개)에 대해 후보·파급·테이블을 명세의 `scopes`에 넣어 둔다. 계산하지 않은 블록으로 옮기면 캔버스가 "Claude 계산 필요"로 표시하고 결정 응답으로 계산 요청을 받는다.
- 손잡이: 사용자가 바꿔볼 만한 설정을 `sweep`으로 미리 측정해 `knobs`에 넣는다.
- 가중치: `table --write`로 민감도를 넣어 두면 사용자가 가중치를 조절할 때 판단 근거가 된다.

## 결정 응답 받기
캔버스의 「결정 요청」 면은 사용자가 답하거나 상태를 바꿨을 때만 `[problem-solving 결정 응답]` 메시지를 만든다(요청 답변, Lens 이동, 가중치 변경, 손잡이, 제외 영역, 메모). 답한 요청은 따르고, 답하지 않은 요청은 기본값을 적용한다(references/autonomous-decision.md). Lens 변경은 2단계로, 가중치 변경은 6단계 재계산으로, 새 Lens 계산 요청은 4~6단계로 이어진다.
