# 가치 비교 테이블

비싸거나 되돌리기 어려운 실행 전에는 반드시 먼저 앉아서 이 테이블을 셈한다. 셈하지 않은 실행은 탑을 기초만 놓고 버리는 일이 되기 쉽다.

행은 Lens 안 후보, 열은 아래 축. 각 축 1~5점, 근거 한 줄을 반드시 붙인다.

| 축 | 의미 |
|---|---|
| 기대 효과 | 성공 시 문제를 얼마나 해결하는가 |
| 판별력 | 실패해도 다음 Lens 결정에 쓸 정보를 얼마나 남기는가 |
| 비용 | 시간·연산·구현 노력 (낮을수록 고득점) |
| 완주 가능성 | 지금 가진 자원(GPU, 시간, 데이터, 사람)으로 끝까지 해낼 수 있는가. 비용이 싸도 중간에 멈출 수밖에 없다면 낮다 |
| 가역성 | 되돌리기 쉬운가 |
| 문제 보존도 | 원래 풀려던 문제(연구 주장, 베이스라인 비교성)를 유지하는가 |
| 파급 위험 | Lens 밖 파급의 크기·확신도 (작을수록 고득점) |
| 근거 강도 | 직접 사례 > 반사실 > 출처 없음, 조건 이식 성립 여부 반영 |

종합 점수는 단순합으로 시작하되, 상황상 특정 축이 결정적이면(예: 마감 직전이면 비용) 가중치를 밝히고 조정한다.

## 변경량 기반 절단
루프와 자율 행동을 횟수가 아니라 무엇이 바뀌었는지로 끊는다.

### 루프 변경량
매 루프 끝에 이번 루프에서 바뀐 것을 기록하고 점수화한다.

| 변경 | 점수 |
|---|---|
| 1순위 후보가 바뀜 | 3 |
| Lens 경계가 바뀜 (넓힘·좁힘·자식 진입·복귀) | 2 |
| 새 후보 추가 또는 후보 기각 | 후보당 1 |
| 1순위 외 순위 변동 | 변동한 후보당 0.5 |
| 테이블 점수 변화 (근거 갱신) | 바뀐 칸 3개당 0.5 |

스프린트 단위로 기록할 때(`sprint.py end`)는 정의 단계의 변화도 센다: 문제 영역 변경 2, 제외·다시 포함 각 1, 닫힌 길 추가 각 1, 새 측정 1, 확인된 사실 각 1, Blueprint 갱신 1.

결정 단계(탐색·경우의 수·결정) 스프린트의 변경량이 두 번 연속 1 이하이면 정보가 포화된 것으로 보고 절단한다. 변경 목록 자체는 보고서의 타임라인에 그대로 남긴다.

### 행동 변경량
한 단계 안의 자율 행동(검색, 코드 읽기, 측정)마다 새 사실(새 후보, 새 조건, 기각, 수치)이 나왔는지 기록한다. 연속 3회 새 사실이 없으면 그 단계를 닫는다.

### 재귀 복귀
자식 Lens 루프의 변경량이 부모 테이블의 1·2순위 관계를 바꿀 수 없는 수준(자식에서 얻을 최대 점수 변화가 부모 1·2순위 점수 차보다 작음)이 되면 부모로 돌아간다.

### 최후 상한
변경량 기준이 작동하지 않는 비정상 상황(같은 변경이 진동하며 반복됨)을 막기 위해, 같은 Lens 경계를 세 번째로 다시 방문하면 진동으로 판단하고 절단한다. 이 경우 보고서에 진동한 두 상태를 명시한다.
