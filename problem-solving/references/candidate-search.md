# 후보 탐색과 이식가능성

## 탐색 순서
1. 직접 사례: 같은 문제를 다룬 논문, GitHub 이슈, 공식 문서, 포럼.
2. 반사실 조절: 직접 사례가 없으면 문제의 조건 하나를 바꿔 인접 문제를 찾는다.
   예) 시퀀스 길이를 줄인다면? 도메인이 이미지였다면? 프레임워크가 달랐다면?
   바꾼 조건은 이식가능성 검토에서 반드시 되짚는다.
   검정 강도는 아래 "반사실 검정 강도"를 따른다.
3. 직관 후보: 근거를 찾지 못했지만 예측이 선명한 후보. `출처 없음`으로 표시한다.

이미 닫힌 길(정렬 단계의 시도 이력)과 겹치는 후보는 왜 이번엔 다른지 설명할 수 있을 때만 올린다.

## 출처 위에서 한 칸 더
출처를 찾는 것은 어깨에 올라서는 것까지다. 더 멀리 보는 것은 이쪽 몫이다. 각 후보에 대해 출처가 다루지 못한 우리 조건의 차이를 한 줄로 적고, 그 차이 때문에 바꿔야 할 점이 있으면 후보를 그만큼 변형한다. 차이를 적을 수 없다면 아직 출처를 충분히 읽지 않은 것이다.

## 후보 카드
- 후보: 무엇을 바꾸는가
- 출처: 링크 또는 `반사실(바꾼 조건)` 또는 `출처 없음`
- 통했던 조건: 출처에서 이 방법이 효과를 낸 환경(도메인, 규모, 하드웨어, 프레임워크, 버전)
- 우리와의 차이: 출처가 다루지 못한 우리 조건 (위 "한 칸 더")
- 결과의 경우의 수: 이 후보를 두었을 때의 성공·부분 성공·실패 분기, 각각의 대략적 확률과 그 분기에서 배우는 것. 캔버스에서 후보 옆으로 펼쳐진다
- 이식가능성: 아래 두 겹

## 근거를 바로 볼 수 있게
후보의 근거는 사용자가 그 자리에서 열어 볼 수 있어야 한다. `evidence`에 넣는다.
- 외부 자료: `{"type": "url", "label": "FlashAttention (arXiv:2205.14135)", "url": "https://..."}` — 실제로 확인한 URL만 넣는다. 기억에 기댄 URL은 넣지 않는다.
- 내부 코드: `{"type": "code", "path": "ts_model/model/attn.py", "lines": "22-25", "snippet": "…", "note": "이 줄을 바꾼다"}` — 사용자 저장소에 근거가 있으면 경로·줄과 함께 코드 조각을 싣는다.
- `check`(검증 강도: 강·중·약)는 캔버스에서 색 배지로 보인다. 반사실 검정 강도와 같은 기준이다.

## 사용자 제안
사용자가 [새 시도 제안]을 보내면 `scripts/sprint.py propose`로 등록하고, 다음 스프린트에서 후보로 올린다(`proposed_by: "user"`). 사용자 제안이라고 깎거나 덮어주지 않는다—출처 탐색, 우리와 다른 점, 이식 가능성, 결과의 갈래, 가치 비교를 다른 후보와 똑같이 거친다. 근거를 찾지 못하면 `check: "약"`과 `출처 없음`으로 두되 후보에서 빼지 않는다. 제안이 Lens 범위 밖을 건드리면 문제 재정의가 필요하다는 결정 요청으로 돌린다.

## 이식가능성 두 겹
- 코드 이식: 프레임워크(TF↔PyTorch), 의존성 버전, 커스텀 커널, API 변경. 비용의 문제다.
- 조건 이식: 통했던 전제가 우리 문제에서도 성립하는가. 도메인, 데이터 길이·분포, 하드웨어 메모리 구조, 규모. 실패하면 코드는 옮겨지는데 효과가 안 옮겨진다. 더 위험하므로 먼저 본다.

코드 이식 비용이 크면 그 후보 안에 자식 Lens를 열어 프로세스를 재귀적으로 돈다. 조건 이식이 깨지면 자식 Lens를 열지 않고 후보 자체를 강등한다.

## 반사실 검정 강도
반사실 확인은 경우의 수를 정량 비교할 근거를 만드는 과정이지만, 가장 쉽게 시간을 삼키는 과정이기도 하다. 강도는 Lens 깊이에 맞춘다.

| 깊이 | 강도 | 방법 | 테이블에 주는 근거 |
|---|---|---|---|
| 0 (거시) | 약 | 사고실험, 문헌상 보고된 효과, 구조적 추론. 실행하지 않는다. | 방향(+/-)과 대략의 크기 |
| 1 (함수·모듈) | 중 | 작은 입력으로 단발 실행, 프로파일러, shape·메모리 추적 | 스케일링 형태(선형/제곱/누수 등) |
| 2 (라인·수치) | 강 | 실제 값을 바꿔 측정, 반복 측정으로 분산 확인 | 수치 단위의 효과 크기 |

거시에서 강한 검정이 필요해 보이면 검정을 키우지 말고 Lens를 좁혀서 미시로 내려간 뒤 검정한다. 검정 결과는 후보 카드의 `counterfactual`에 강도와 함께 기록하고, 테이블의 기대 효과·근거 강도 점수에 반영한다. 약한 검정에서 나온 점수는 강한 검정 점수와 같은 확신으로 다루지 않는다.
