# problem-solving

막힌 문제를 **해설하지 않고 수를 두어** 푸는 Claude 스킬입니다.
코드를 정보 흐름대로 펼친 **Blueprint** 위에서 **Lens**를 옮겨 가며, 근거 있는 후보를 찾고, 두면 생길 일을 견주어, 다음 수를 고릅니다.

! [Lens와 옆에 이어 붙는 카드](docs/images/02-lens.png)

OOM, 학습 발산·미수렴, 반복되는 에러, 성능 정체, 재현 실패, 논문 방법 이식, 막힌 설계 결정에 씁니다.
"왜 안 되지", "계속 같은 문제가 나", "해 볼 건 다 해 봤는데" 같은 말이 나오면 스킬을 부르지 않아도 동작합니다.

## 시작하기

### 설치
- **Claude Code**: 이 폴더를 `.claude/skills/problem-solving/`(이 저장소에서만) 또는 `~/.claude/skills/problem-solving/`(모든 프로젝트)에 둡니다.
- **claude.ai**: 이 폴더를 zip으로 묶어 스킬로 올립니다. 압축 파일 맨 위에 `problem-solving/` 폴더가 오게 묶습니다.

필요한 것은 Python 3뿐입니다. 스크립트는 표준 라이브러리만 쓰고, 캔버스 HTML은 외부 리소스 없이 열립니다.

### 최소 입력
두 가지만 있으면 시작합니다.

| 필요한 것 | 예 |
|---|---|
| 무엇이 안 되는가 | 학습 중에 계속 OOM이 난다 |
| 그게 어디에 있는가 | `ts_model/train.py` |

```
ts_model/train.py 돌리면 계속 OOM 나. 배치 줄여 봤는데 안 돼.
```

이미 해 본 것, 바꾸면 안 되는 것, 가진 자원과 기한은 첫 스프린트(정렬)에서 한 번에 묻습니다. 모르면 비워 둔 채 진행합니다.

## 화면 둘러보기

### Blueprint와 지금 상황
코드를 정보가 흐르는 순서대로 블록으로 펼칩니다. 빗금 테두리가 문제로 정한 곳이고, 왼편 바깥의 「지금 상황」이 문제·사실·현재 스프린트·가장 앞선 수를 한눈에 정리합니다.

![Blueprint 전체와 지금 상황](docs/images/01-blueprint.png)

배치는 그리기 전에 코드와 문제를 보고 정합니다. 짧은 파이프라인은 가로, 긴 순차 흐름은 세로, 갈래가 많은 시스템은 격자입니다.

![가로·세로·격자 배치](docs/images/06-layouts.png)

### Lens
Lens는 Blueprint 위를 움직이는 초점입니다. 안은 선명하고 바깥은 흐려집니다. 진행 중인 스프린트의 Lens는 테두리가 천천히 돕니다.

Lens 옆에는 스프린트가 나아간 만큼 카드가 순서대로 붙습니다.

**지금 보는 곳 → 둘 수 있는 수 → 두면 생길 일 → 견주어 보기 → 바꿔 볼 수 있는 값 → 정해 주실 것**

Lens는 Claude가 코드의 처리 흐름을 따라 옮기되, 문제 영역의 하위이거나 문제 영역과 직결된 블록 안에서만 움직입니다. 그 밖으로 가야 한다면 문제를 다시 정의하는 일이므로 사용자에게 묻습니다.

### 영향이 닿는 곳
Lens 단위에서 관련된 다른 프로세스의 블록을 Lens 위로 꺼내 놓습니다. 후보에 마우스를 올리면 그 수가 영향을 주는 블록까지 선이 흐르고, 원래 자리까지 점선이 이어집니다.

![후보에 마우스를 올렸을 때의 영향선](docs/images/04-influence.png)

### 이 수를 두면
후보를 누르면 갈래가 펼쳐집니다. 출처 및 근거(논문 링크, 내부 코드 위치), 이식 가능성, 성공·부분 성공·실패의 확률과 각 경우에 얻는 정보, 파급 영향이 선으로 이어집니다.

![후보의 갈래 펼침](docs/images/03-branches.png)

### 정해 주실 것
Claude는 사용자의 판단이 결과를 바꾸는 지점에서만 묻습니다. 답이 없으면 정해진 범위 안에서 스스로 고르고, 그 사실을 다음 답의 첫 줄에 밝힙니다. 언제든 완전히 새로운 시도를 제안할 수 있고, 제안은 다음 스프린트에서 다른 후보와 똑같이 따집니다.

<img src="docs/images/05-ask.png" alt="결정 요청과 새 시도 제안" width="320">

### 선의 문법
선 모양은 얼마나 확실한지를, 색은 무슨 관계인지를 나타냅니다.

| 선 | 뜻 |
|---|---|
| 실선 | 확인된 관계 (측정했거나 출처가 직접 보임) |
| 점선 | 예측·가설 |
| 흐린 선 | 약하거나 간접적인 영향 |
| 보라 / 주황 / 초록 / 빨강 | 근거와 흐름 / 바깥 블록의 자체 반응 / 함께 쓰면 좋음 / 서로 부딪힘 |

캔버스는 기본이 밝은 테마이고, 오른쪽 위 버튼으로 어둡게 바꿀 수 있습니다.

## 어떻게 푸나

| 단계 | 하는 일 |
|---|---|
| 1. 정렬 | 사용자의 말과 틀 그대로 문제를 다시 적고, 본 것과 해석을 나누고, 이미 닫힌 길을 확인 |
| 2. 범위 | 반복되는 증상을 묶어 공통 출발점을 찾고, 그 출발점이 증상을 모두 설명하는지 검증. 문제 영역 표시 |
| 3. 깊이 | 해결에 필요한 만큼만 블록을 쪼갬. 국소적이면 깊이, 반복되면 폭 |
| 4. 탐색 | 선행연구·웹 → 조건을 비튼 인접 문제 → 직관 순으로 후보를 찾고, 근거와 이식 가능성을 붙임 |
| 5. 경우의 수 | 수마다 바깥 블록에 생기는 일을 펼침. 가까운 곳은 선명하게, 먼 곳은 흐리게 |
| 6. 결정 | 정량 가치 비교로 다음 수를 고름. 필요한 경우에만 사용자에게 요청 |

작업은 **스프린트** 단위로 보입니다. Claude가 단계가 바뀔 때, Lens를 옮길 때, 코드가 갱신될 때 스스로 선언합니다. 멈추는 기준은 횟수가 아니라 변경량입니다. 결정 단계의 스프린트가 두 번 연속으로 결정을 바꾸지 못하면 정리해 보고합니다.

## 도구

| 스크립트 | 하는 일 |
|---|---|
| `scripts/render_step.py` | 명세(JSON)를 Blueprint·Lens 캔버스 HTML로 그림 |
| `scripts/quant.py sweep` | 손잡이(길이·배치·정밀도…) 격자마다 실행해 측정. 실패(OOM 등)도 경계로 기록 |
| `scripts/quant.py scaling` | y = c + a·xᵏ 적합으로 상수/선형/제곱 판별. 고정 비용에 속지 않음 |
| `scripts/quant.py leak` | 스텝에 따라 늘어나는지(누수) 판별 |
| `scripts/quant.py table` | 가치 비교 종합 점수와, 무게를 흔들어도 1위일 가능성 |
| `scripts/quant.py decide` | 사용자에게 물어야 하는지와, 답이 없을 때 고를 수 |
| `scripts/sprint.py` | 스프린트 시작·종료(변경량 기록), Blueprint 갱신, 사용자 제안 등록 |

```bash
python scripts/quant.py sweep --cmd "python probe.py --L {L} --B {B}" \
  --grid '{"L":[1024,2048,4096,8192],"B":[1,2,4]}' --out sweep.json
python scripts/quant.py scaling sweep.json --x L --y mem_gb --group B
python scripts/sprint.py start spec.json --stage 탐색 --lens attn --goal "L² 항을 줄이는 선행연구 탐색"
python scripts/render_step.py spec.json canvas.html
```

전체 명세 예시는 [`examples/oom_spec.json`](examples/oom_spec.json)에 있습니다.

## 단계마다의 격언

각 단계의 태도는 원문 그대로 인용한 격언으로 세웁니다. 지침이 다루지 않는 상황에서는 격언이 판단 기준입니다. 원문·번역·출처는 [`config/values.yaml`](config/values.yaml)에 있습니다.

| 자리 | 격언 |
|---|---|
| 문제해결의 본질 | 릴케, 《젊은 시인에게 보내는 편지》 — 질문 그 자체를 사랑하라 |
| 정렬 | 키르케고르, 《저술가로서 나의 작업에 대한 관점》 — 그가 서 있는 곳에서 시작하라 |
| 범위 | 뉴턴, 《프린키피아》 철학함의 규칙 I·II |
| 깊이 | 데카르트, 《방법서설》 — 가능한 만큼, 필요한 만큼 나눌 것 |
| Blueprint | 블레이크, 「순수의 전조」 · 마셜, 《경제학 원리》 |
| 탐색 | 솔즈베리의 존, 《메탈로기콘》 · 뉴턴, 훅에게 보낸 편지 — 거인의 어깨 |
| 경우의 수 | 바스티아, 「보이는 것과 보이지 않는 것」 · 스미스, 《도덕감정론》 |
| 결정 | 누가복음 14:28, 31 — 먼저 앉아서 셈하라 |
| 종료 | 전도서 11:4 · 케인스, 《화폐개혁론》 |
| 결정 요청과 자율 결정 | 히포크라테스, 《유행병》 · 노자, 《도덕경》 44장 |
| 설명과 정리 | 부알로, 《시학》 · 《논어》 위령공 |

## 알아 둘 점
- **인용 원문**: 격언 중 일부(그리스어·히브리어 원문, 스미스, 마셜, 히포크라테스)는 판본 대조가 필요합니다. `values.yaml`에 표시해 두었습니다.
- **실측**: `quant.py sweep`의 실제 GPU 측정은 연구자의 장비에서 돌 때(예: Claude Code) 의미가 있습니다. 예시의 측정값은 GPU 없이 메모리를 흉내 낸 `probe_toy.py`에서 나왔습니다.
- **피드백 전달**: 캔버스의 「Claude에게 전하기」는 claude.ai의 시각화 안에서만 바로 보냅니다. 파일로 열면 클립보드에 복사합니다.
